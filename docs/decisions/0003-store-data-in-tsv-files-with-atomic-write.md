# Хранение данных в TSV-файлах с атомарной записью

## Контекст и постановка задачи

Данные (пользователи, оборудование, брони) должны сохраняться после каждого изменения и переживать перезапуск (REQ-REL-001). Объём — сотни записей, один пользователь одновременно. Внешние библиотеки и сервер СУБД нежелательны (ADR-0001). Как хранить данные?

## Драйверы решения

* Надёжность: сбой при записи не должен портить базу (REQ-REL-001).
* Нет внешних зависимостей и установки СУБД (REQ-INST-001).
* Возможность заменить хранилище позже (SRS 3.5.6).

## Рассмотренные варианты

* Текстовые TSV-файлы + запись через временный файл и `ATOMIC_MOVE`
* Встраиваемая СУБД H2/SQLite через JDBC
* Сериализация Java-объектов в один бинарный файл

## Итог решения

Выбранный вариант: «TSV + атомарная запись», потому что он не требует зависимостей, файлы читаются человеком (удобно при проверке и резервном копировании), а доступ изолирован в классе `Store`, поэтому переход на JDBC затронет только его.

### Последствия

* Хорошо, потому что `data/` можно скопировать как резервную копию.
* Хорошо, потому что запись атомарна — на диске либо старая, либо новая версия файла.
* Плохо, потому что вся таблица перезаписывается при каждом изменении (для сотен строк — миллисекунды).
* Плохо, потому что нет конкурентного доступа; два экземпляра приложения не поддерживаются (V-011).

### Подтверждение

Автоматическая проверка REQ-REL-001: изменить данные, создать новый `Store` на том же каталоге и сравнить состояние.

## Плюсы и минусы вариантов

### TSV + атомарная запись

* Хорошо, потому что прозрачно и без зависимостей.
* Плохо, потому что нет индексов и транзакций между таблицами.

### H2 / SQLite через JDBC

* Хорошо, потому что транзакции и SQL.
* Плохо, потому что нужен JAR-драйвер — нарушает «только JDK».

### Сериализация Java

* Хорошо, потому что минимум кода.
* Плохо, потому что формат ломается при изменении классов (а версия 1.0 меняет `Booking`).

## Дополнительная информация

Пересмотреть при переходе на многопользовательский сетевой режим. В версии 1.0 формат `bookings.tsv` расширен (ADR-0007), старые файлы переводятся в новый формат при загрузке. Связано: V-004, V-007, V-011.
