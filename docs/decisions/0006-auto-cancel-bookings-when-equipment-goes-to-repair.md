# Автоматическая отмена броней при переводе оборудования в ремонт

## Контекст и постановка задачи

Неисправный прибор нельзя выдавать (REQ-FUNC-005). Но на него уже могут быть оформлены брони. Что делать с ними при переводе в ремонт?

## Драйверы решения

* Студент не должен прийти за неисправным прибором (бизнес-цель SRS 1.2).
* Лаборант не должен вручную искать и отменять брони.
* Прозрачность: студент видит причину отмены.

## Рассмотренные варианты

* Автоматически отменить действующие брони с примечанием
* Запретить перевод в ремонт, пока есть брони
* Оставить брони и только предупредить лаборанта

## Итог решения

Выбранный вариант: «Автоматическая отмена», потому что неисправность не ждёт окончания броней, а отмена с примечанием «Оборудование переведено в ремонт» сразу видна студенту. Лаборант видит число отменённых броней.

Уточнение от 27.10.2026 (ADR-0007): если по брони прибор уже **выдан** (ISSUED), перевод в ремонт запрещён, пока лаборант не примет прибор.

### Последствия

* Хорошо, потому что нет «висящих» броней на сломанный прибор.
* Плохо, потому что студент узнаёт об отмене, только открыв приложение (уведомления вне рамок проекта).

### Подтверждение

Автоматическая проверка: две брони → перевод в ремонт → обе CANCELLED с примечанием, возвращено число 2; при ISSUED-брони — отказ.

## Плюсы и минусы вариантов

### Автоматическая отмена

* Хорошо, потому что одно действие лаборанта.

### Запрет перевода

* Плохо, потому что сломанный прибор продолжит числиться исправным.

### Только предупреждение

* Плохо, потому что брони на неисправный прибор останутся действующими.
