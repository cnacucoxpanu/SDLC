# Экспорт CSV для Excel: разделитель «;» и UTF-8 с BOM

## Контекст и постановка задачи

Для ежегодной инвентаризации заказчику нужна выгрузка каталога и журнала выдачи в файл, который открывается в Excel двойным щелчком (REQ-FUNC-009). Данные на русском языке. Какой формат выгрузки выбрать?

## Драйверы решения

* Excel с русской локалью ожидает разделитель «;», а без BOM показывает UTF-8 нечитаемыми символами.
* Только стандартная библиотека JDK (ADR-0001).
* Задачу выполняет junior-разработчик — формат должен быть простым.

## Рассмотренные варианты

* CSV: UTF-8 с BOM, разделитель «;», кавычки по RFC 4180
* CSV: UTF-8 без BOM, разделитель «,»
* XLSX через Apache POI

## Итог решения

Выбранный вариант: «CSV, UTF-8 с BOM и разделителем ;», потому что только он открывается в Excel заказчика без мастера импорта и не требует библиотек.

### Последствия

* Хорошо, потому что файл открывается двойным щелчком.
* Плохо, потому что в Excel с другой локалью может понадобиться импорт вручную.

### Подтверждение

Автоматическая проверка: первые байты файла — `EF BB BF`; поле с «;» и кавычками экранируется. Ручная проверка: файл открыт в Excel на компьютере лаборатории.

## Плюсы и минусы вариантов

### CSV с BOM и «;»

* Хорошо, потому что совместимо с Excel заказчика.

### CSV без BOM с «,»

* Плохо, потому что кириллица и столбцы ломаются в русском Excel.

### XLSX (Apache POI)

* Хорошо, потому что получается полноценный файл Excel.
* Плохо, потому что внешняя библиотека около 20 МБ и +8 ч работы.

## Дополнительная информация

Связано: REQ-FUNC-009, V-005.
