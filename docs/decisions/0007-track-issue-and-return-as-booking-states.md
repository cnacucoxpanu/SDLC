# Выдача и возврат оборудования как состояния брони

## Контекст и постановка задачи

Во втором раунде обсуждения заказчик добавил обязательную функцию: журнал фактической выдачи и возврата оборудования с подсветкой просроченных возвратов (REQ-FUNC-008, приоритет 10). Раньше бронь имела только поле `active` (активна / отменена). Как хранить факты выдачи и возврата?

## Драйверы решения

* Срок релиза 29.12.2026 не сдвигается — нужен самый дешёвый надёжный вариант.
* Правила должны оставаться согласованными: нельзя выдать отменённую бронь, нельзя отправить в ремонт выданный прибор.
* Совместимость с файлами данных прототипа (ADR-0003).

## Рассмотренные варианты

* Расширить `Booking`: перечисление `BookingState` (ACTIVE, ISSUED, RETURNED, CANCELLED) и даты `issuedOn`, `returnedOn`
* Отдельная таблица `issues.tsv` (журнал), связанная с бронью
* Выдача без брони (отдельный журнал «кто что взял»)

## Итог решения

Выбранный вариант: «Расширить Booking состояниями», потому что выдача всегда происходит по брони, одна запись описывает один жизненный цикл, а правила переходов проверяются в одном месте (`IssueService`). Оценка — 40 ч против примерно 52 ч для отдельной таблицы.

### Последствия

* Хорошо, потому что журнал — это фильтр по броням, без дублирования данных.
* Хорошо, потому что «Просрочена» вычисляется (ISSUED и `to` < сегодня), а не хранится.
* Плохо, потому что меняется формат `bookings.tsv` — нужна миграция при загрузке (`true` → ACTIVE, `false` → CANCELLED).
* Плохо, потому что затрагиваются готовые функции: отмена (нельзя отменить ISSUED), ремонт (запрет при ISSUED), просмотр броней (новые статусы).

### Подтверждение

Автоматические проверки F-16c: выдача только в период брони; повторная выдача и возврат невыданной брони отклоняются; миграция старого файла; запрет ремонта при ISSUED.

## Плюсы и минусы вариантов

### Состояния брони

* Хорошо, потому что минимум новых сущностей.
* Плохо, потому что нужна миграция формата.

### Отдельная таблица issues

* Хорошо, потому что старый формат не меняется.
* Плохо, потому что нужно согласовывать две таблицы, +12 ч.

### Выдача без брони

* Плохо, потому что ломает правило «без конфликтов»: прибор можно выдать в обход брони.
